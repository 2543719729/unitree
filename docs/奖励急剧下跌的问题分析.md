# 奖励急剧下跌的问题分析

本文聚焦你在 **Unitree G1 盲爬楼梯训练**中观察到的现象：

- 训练过程中 episode reward（或其滑动平均）波动极大
- 训练到某一阶段后，reward 可能出现“快速下跌/崩盘”，并且恢复很慢或难以恢复

该现象通常不是单一原因导致，而是 **环境难度分布变化（curriculum）**、**奖励塑形/权重非平稳**、**终止条件分布变化** 与 **PPO 更新不稳定** 共同作用的结果。

---

## 0. 先澄清：你看到的 reward 是什么？

在 Isaac Lab 的 Manager-based RL 框架里：

- 每一步总奖励为：`sum_i( term_i(env) * weight_i * dt )`
- 日志里常见的 `Episode_Reward/<term_name>` 是：
  - 对 reset 的 env 求 episodic sum 的均值
  - 再除以 `max_episode_length_s` 做到“每秒”尺度（而不是按实际 episode 时长归一化）

因此：

- **episode 提前终止（episode_length 变短）**会显著拉低日志里的每秒 reward
- **某个大权重惩罚项增加**（例如姿态惩罚/接触惩罚）会让总 reward 迅速下跌，即使 `upward_progress` 在上升

建议在出现下跌时，同时查看：

- `Episode_Reward/upward_progress`
- `Episode_Reward/track_lin_vel_xy`
- `Episode_Reward/flat_orientation_l2`
- `Episode_Reward/undesired_contacts`
- `Termination/<term>` 统计（尤其是 `bad_orientation`、`base_height`）

---

## 1. 最常见根因：环境难度分布“突变”（Curriculum/Domain Randomization）

### 1.1 地形 curriculum：大量并行环境同时升级 → 训练分布突然变了

Isaac Lab 的 terrain curriculum 本质是：在 reset 时对 `env_ids` 计算 `move_up/move_down`，然后

- `terrain_levels[env_ids] += 1 * move_up - 1 * move_down`
- `env_origins[env_ids]` 随 `terrain_levels` 改变，机器人出生点跳到更难的 row

如果升级条件只基于存活（或阈值过低），会出现：

- 一段时间策略只是在“更容易的地形上学会不倒”
- 一旦达到 upgrade 阈值，**同一批 reset env 会快速升级到更难地形**
- 总 reward 会出现显著下跌（因为任务突然更难，终止率上升、惩罚项变大）

这类下跌**并不一定是算法崩溃**，而是分布变化导致的“阶段性掉分”。

你目前已经把 `terrain_levels` 从纯存活升级切换为：

- `terrain_levels_survival_with_height`
- 升级需同时满足：`survival_ratio` 与 `upgrade_height`

这会显著降低“仅靠苟住就升级”的概率，减少分布突变。

### 1.2 TerrainGenerator 的一个容易误判点：sub-terrain 类型按列固定，不是按行

在 `TerrainGenerator` 的 curriculum 模式中：

- **每一列的 sub-terrain 类型**由 `proportion` 决定（列区间固定）
- **每一行的 difficulty**随 `row` 增大而增大

因此即使 `max_init_terrain_level=0`：

- `terrain_levels=0` 只表示 difficulty 很低
- 但不同列仍可能是 stairs（只是 step_height 接近该 stairs 的下限）

这会导致你以为“Level 0-2 全平地”，但实际上仍会混入楼梯列，只是难度更低。

这种“你以为的 curriculum”与“实际 curriculum”不一致，会放大训练波动。

**缓解建议（按侵入性从低到高）：**

- 低侵入：把升级阈值调高/加稳定计数，保证真正学会再升级
- 中侵入：把 `sub_terrains` 的 `proportion` 设计成早期更多平地列，后期才引入楼梯列
- 高侵入：分两阶段训练：
  - Stage0：只启用 flat
  - Stage1：再启用 stairs（从 checkpoint resume）

### 1.3 速度命令 curriculum：命令范围扩张也会造成 reward “阶段性下跌”

你使用了 `lin_vel_cmd_levels`：当 `track_lin_vel_xy` 评估超过阈值，会把 `ranges.lin_vel_x/lin_vel_y` 以固定步长扩大。

扩大命令范围的瞬间，策略会遇到更难的跟踪任务：

- 速度更快 → 更容易摔倒 → `bad_orientation/base_height` 终止增加
- 足端更容易打滑/非预期接触 → 惩罚项变大

这会表现为 reward 下降（常见）。

**缓解建议：**

- 降低每次扩张步长（例如 0.1 → 0.05 或更小）
- 增加“连续成功次数”条件（避免一次偶然成功就升级）
- 把命令 curriculum 推迟到地形 curriculum 稳定后再开启

### 1.4 域随机化强度过大/施加时机不对 → 训练方差大、易崩

例如：

- 摩擦系数随机范围过宽（0.4~1.0）
- 质量随机、推力随机

如果在策略尚未稳定前就加入强随机化，常见现象是：

- reward 波动大
- 一旦策略刚学到某个动作模式，遇到随机化条件变化就掉分

**缓解建议：**

- 先收窄随机化范围，等策略稳定后逐步放开
- 或者把随机化也做成 curriculum（强度随训练增长）

## 2. 奖励“看似合理但实际在打架”：奖励项冲突导致总 reward 下跌

当策略开始尝试“真正爬楼动作”时，以下项可能同步变坏：

- `flat_orientation_l2`（权重较大，倾斜/摆动会快速产生负回报）
- `undesired_contacts`（摔倒或膝盖/手臂接触会触发）
- `feet_slide`（楼梯边缘滑动）
- `joint_deviation_knees`（爬楼往往需要更大屈膝，可能被惩罚压制）

这会导致：

- `upward_progress` 有提升，但 **总 reward 反而下降**

**如何确认是否是“奖励打架”导致的掉分：**

- 在 reward 下跌的窗口，检查各 term 的 `Episode_Reward/<term>`
- 如果 `upward_progress` 上升但某几个惩罚项大幅变负，则需要重新平衡权重/形状

**常见修复策略：**

- 让惩罚项随阶段递增（早期弱惩罚、后期强约束），避免一开始就“抑制探索”
- 对膝关节惩罚改为“只惩罚极端屈膝”，不要惩罚正常爬楼所需屈膝
- 把“姿态惩罚”从 L2 改为带阈值（小角度不惩罚，大角度再强惩罚）

---

## 3. 终止条件分布变化：终止变早 → 每秒 reward 会突然掉

你已经观察到 `bad_orientation` 占比很高。

当以下任一项发生变化时，会造成 reward 快速下跌：

- 地形更难 / 命令更快 → 倾倒更频繁
- `limit_angle` 变严格（如果使用自适应阶段切换）
- `minimum_height` 太高或不匹配地形基准

**建议重点看两类信号：**

- `Mean Episode Length` 是否突然下降
- `Termination` 各项占比是否突然上升

**缓解建议：**

- 训练早期放宽 `bad_orientation` 的阈值，后期再逐步收紧
- 增大 grace steps，避免 reset 初期抖动触发早终止
- 若发现“摔倒后不终止、躺着耗完 episode”，需要增加更可靠的失败检测（例如接触/姿态组合）

---

## 4. PPO/策略更新不稳定：真正的“训练崩盘”通常伴随这些指标

如果 reward 下跌同时伴随：

- KL divergence 飙升
- entropy 迅速下降（策略塌缩）
- value loss 爆炸 / explained variance 变差

则更可能是 **优化不稳定** 而非仅 curriculum 分布变化。

**高概率诱因：**

- reward scale 突然变化（例如 curriculum/权重跳变）导致 advantage 尺度突变
- 学习率过高 / clip 太激进
- value function 跟不上分布变化

**缓解建议（通用）：**

- 降低学习率或启用更保守的 schedule
- 增强 KL 约束（更小的 target_kl）
- 开启/强化 reward normalization（或对 advantage 做标准化）
- curriculum 改为“渐变”而非“跳变”

---

## 5. 定位流程（强烈推荐按这个顺序做）

### 5.1 先判断：是“环境变难导致掉分”还是“算法崩盘”？

- **只在固定地形/固定命令范围评估（不更新 curriculum）**
  - 如果固定评估也掉分 → 更可能是策略崩盘/优化不稳定
  - 如果固定评估稳定，但训练曲线掉分 → 更可能是 curriculum 分布变化

### 5.2 关联分析：reward 下跌点与哪一类事件同步？

在下跌发生的迭代附近记录：

- `Curriculum/terrain_levels` 均值与分布
- 命令范围（ranges/limit_ranges 的当前值）
- `Termination` 占比（bad_orientation/base_height/time_out）
- 每个 reward term 的 per-second log

通常你能看到一条非常清晰的同步关系：

- terrain_levels 突然上升 / 命令范围扩大 / 终止率升高

## 6. 针对你当前楼梯盲爬项目的“优先级建议”

### P0（立刻做，性价比最高）

- 继续使用 `terrain_levels_survival_with_height`，并根据实际楼梯阶高调整 `upgrade_height`
- 在 reward 下跌时，优先确认是否是 `bad_orientation` 或 `undesired_contacts` 激增

### P1（减少训练波动）

- 放慢命令 curriculum 扩张速度（步长更小 + 连续成功次数）
- 若 terrain curriculum 仍有“批量升级”导致掉分，可考虑：
  - 在 move_up 上加一个概率（例如只让一部分升级）
  - 或者引入“稳定计数”机制

### P2（奖励更贴合爬楼本质）

- 如果 `upward_progress` 长期很低，说明策略并未真正产生持续爬升：
  - 需要检查是否被惩罚项压制
  - 或者改用更不稀疏的进展信号（例如你已有的 `radial_distance_progress`）并重新配权

### P3（如果确认是 PPO 崩盘）

- 调小学习率/加强 KL 约束
- 避免 reward 权重或任务难度发生“跳变”

---

## 7. 结论

“奖励急剧下跌”最常见并且最符合你当前配置的解释是：

- **curriculum（地形/命令）带来的任务分布突变** + **终止率上升** + **大权重惩罚项增强**

当你把 terrain 升级条件从“只看存活”改为“存活 + 爬升高度”后，通常可以显著缓解：

- terrain_levels 虚高
- 难度升级过快
- reward 曲线阶段性崩盘

如果仍然下跌，则按本文的定位流程，进一步区分：

- curriculum 分布变化导致的正常掉分
- PPO 更新不稳定导致的策略崩盘
